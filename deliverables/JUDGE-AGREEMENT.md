Using ``load_only()`` with multiple entities
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

towards in its list of attributes (passing a list of attributes that span more

```
No, `session.scalar(stmt)` is not equivalent to `session.execute(stmt).scalar_one_or_none()` in SQLAlchemy 2.0. 

The `session.scalar(stmt)` method is used to execute a statement and return a single scalar value. If no rows are returned, it returns `None`. If more than one row is returned, it raises an error.

On the other hand, `session.execute(stmt).scalar_one_or_none()` is used to execute a statement and return a single scalar value. If no rows are returned, it returns `None`. If one row is returned, it returns the scalar value from that row. If more than one row is returned, it raises an error.

The key difference is that `session.scalar(stmt)` does not perform any checks on the number of rows returned, while `session.execute(stmt).scalar_one_or_none()` ensures that only one row is returned before returning the scalar value.

This distinction is important when migrating from SQLAlchemy 1.4 to 2.0, as the behavior of these methods has changed to align more closely with the unified query API introduced in SQLAlchemy 2.0.
```
